     Your originals are nested: <group>/images/<file>.jpg

SECTION 3: CRITICAL BUGS IN METRIC CODE
-------------------------------------------------------------

BUG 1 -- Mask evaluator measures the wrong region [CRITICAL]
  File: evaluate_with_mask.py -> calculate_single_pair_metrics()

  After compositing, SSIM/PSNR/LPIPS are computed on the FULL image.
  But the non-mask region is pixel-identical to the original by construction.
  Only the masked region contains signal, so metrics are dominated by
  the always-perfect non-mask region.

  Example: a model generating pure noise inside the garment mask covering
  10% of the image still scores SSIM ~= 0.98 -- completely misleading.

  Fix: Extract masked region before computing metrics:
    orig_masked = original_img * mask_3ch
    comp_masked = composite_img * mask_3ch
    ssim = calculate_ssim(orig_masked, comp_masked)

BUG 2 -- SSIM API crash on scikit-image >= 0.19 [CRITICAL]
  File: metrics/image_quality.py, line ~53

  Current code:
    ssim(img1, img2, multichannel=True, channel_axis=-1, data_range=255)

  `multichannel=True` was removed in scikit-image >= 0.19.
  Passing both multichannel and channel_axis raises TypeError.

  Fix:
    ssim(img1, img2, channel_axis=-1, data_range=255)

BUG 3 -- save_best_worst_samples shows wrong images [CRITICAL]
  File: utils/image_utils.py -> save_best_worst_samples()

  After sort_values(), sorted_df.index[i] is the original pandas row
  label, not a sequential position. If any image pair fails and is
  skipped, the DataFrame index no longer aligns with the image_pairs
  list -> silently loads wrong images for best/worst comparisons.

  Fix: Use file paths embedded in the DataFrame (results already contain
  'original_file'/'generated_file') instead of list indexing.

BUG 4 -- edge_consistency NaN/crash on white garments [CRITICAL]
  File: metrics/image_quality.py -> edge_consistency()

  Current code:
    edge_ssim = ssim(edge1, edge2, data_range=edge1.max() - edge1.min())

  For a solid white garment, max - min ~= 0 -> division by zero or NaN.
  This is exactly the failure case most likely for white ao dai.

  Fix:
    edge_ssim = ssim(edge1, edge2, data_range=max(float(edge1.max()), 1e-6))

SECTION 4: IMPORTANT ISSUES
-------------------------------------------------------------

ISSUE 1 -- Wrong LPIPS backbone in configs
  File: config.yaml and config_masked.yaml

  Both configs use:  net: "alex"  (AlexNet backbone)
  Spec requires:     net: "vgg"   (VGG backbone)

  AlexNet and VGG LPIPS scores are not comparable to VITON-HD/CatVTON
  paper benchmarks which use VGG.

ISSUE 2 -- color_histogram_distance cannot detect ao dai color drift
  File: metrics/image_quality.py

  Current implementation: RGB chi-square distance on independent channels.
  This CANNOT detect white->yellow/gray color drift because:
  - Operates in RGB, not HSV -- hue shifts are not isolated
  - Chi-square on independent channels misses correlated shifts
  - Not alignment-invariant (spec requires alignment-invariant metric)

  Needs replacement with HSV-based Earth Mover's Distance:
    from scipy.stats import wasserstein_distance
    # Convert to HSV, compute per-channel histogram, then wasserstein_distance

ISSUE 3 -- CLI double-reload bug in evaluate_with_mask.py
  File: evaluate_with_mask.py, lines ~577-594

  If user passes both --results_dir and --original_dir, image_pairs is
  reloaded twice. The first reload uses the stale original_dir from config.

  Fix: Apply all CLI overrides to config first, then reload once (same
  pattern as evaluate.py's override_config method).

ISSUE 4 -- FID instead of KID (wrong metric for small datasets)
  File: metrics/image_quality.py -> FIDMetric class

  Spec explicitly requires KID (Kernel Inception Distance) instead of FID
  because FID requires >= 2,048 images for statistical validity.
  Current dataset has ~154 pairs -> FID is statistically unreliable.

ISSUE 5 -- Composite score formula is wrong
  File: utils/image_utils.py

  Current code: composite = (ssim + (1 - lpips)) / 2

  Spec defines 7-component weighted formula:
    20% x Color EMD Score
    25% x NBRLS
    20% x Garment IoU
    15% x DISTS
     5% x SSIM
     5% x LPIPS
    10% x KID

  Current formula is displayed to user as "Composite Quality Score"
  with no caveat -- misleading.
